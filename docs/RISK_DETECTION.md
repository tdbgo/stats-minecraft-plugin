# Stats — 테러/그리프 위험 감지(아이디어)

여기서 “테러”는 서버 내 **그리핑/파괴 행위**(대량 파괴, 컨테이너 파손, 악성 월드편집 등)를 의미합니다.  
`Stats`가 수집하는 지표를 이용해 **조기 경보(early warning)** 시스템을 만드는 것은 가능합니다. 다만 “자동 처벌”보다 **스태프 알림 + 상황 확인** 중심이 안정적입니다(오탐/권한/이벤트 상황 반영).

## 1) 무엇을 감지할지(위협 모델)
- 대량 파괴: 짧은 시간에 블록 파괴량 급증(특히 컨테이너/문/레드스톤 등)
- 기지 테러: 특정 유형(컨테이너/침대/문/레일/레드스톤) 타격 집중
- 악성 WorldEdit/FAWE: `//set`, `//replace`, `//paste` 등 고위험 커맨드 사용 급증(권한 없는 계정의 사용은 특히 위험)
- 신규 계정 테러: “첫 접속 후 짧은 시간 내 파괴 행동 집중” 패턴

## 2) 현재 카탈로그로 가능한 신호(좌표 없이)
아래 신호는 `docs/DATA_CATALOG.md`의 집계 기반 데이터만으로도 산출 가능합니다.
- `Container Break Spike`: `container` 그룹(상자/배럴/셔커 등) 파괴량이 개인 기준/서버 기준 급증
- `Destruction Ratio`: `blocks_broken_total / (blocks_placed_total + 1)`가 짧은 창에서 비정상적으로 큼
- `WorldEdit High-Risk Usage`: `worldedit:set`, `worldedit:replace`, `worldedit:paste` 사용(특히 신규 계정/비빌더)
- `Command Spam`: 5~10분 창에서 커맨드 수 급증(매크로/도구 오남용)
- `AFK Disqualifier`: AFK 비율이 높으면 “오탐(활동 없음)” 케이스로 감점(= 활동 기반 신호 강화)

## 3) 실시간 경보를 위한 최소 추가 설계(권장)
현 구조가 hour/day 중심이라면, “경보”는 최소한 **짧은 시간창(예: 5분)** 집계가 필요합니다.
- 구현 방식(권장):
  - 메모리에서 `player × 5min bucket` 카운터를 누적
  - 5분마다 DB 업로드(이미 합의된 플러시 주기와 정합)
  - 경보는 메모리 상의 카운터로 즉시 평가(업로드를 기다릴 필요 없음)
- 저장 테이블은 선택:
  - 영구 보관이 부담이면 “경보 이벤트(알림 로그)”만 저장하고 5분 버킷은 저장하지 않아도 됨

## 4) 위험 점수(Score) 접근(권장)
단일 규칙만으로는 오탐이 많으므로, 여러 신호를 조합한 점수화를 권장합니다.

예시(개념):
- `risk = w1*container_break + w2*block_break + w3*worldedit_ops + w4*new_account_bonus - w5*builder_behavior`
- 평가 창: 최근 5분 + 최근 30분(EWMA/가중 이동평균)
- 기준선:
  - 개인 기준선(자기 평소 대비): 최근 7일/30일의 중앙값 대비 z-score(강건 통계)
  - 서버 기준선(전체 대비): 동시간대 평균/분산으로 보정(이벤트/피크 시간대 대응)

## 5) 오탐을 줄이는 게이트(매우 중요)
- 권한 기반 게이트:
  - `worldedit.*`/`fawe.*` 권한자(빌더/스태프)는 별도 임계치 또는 감시 레벨 분리
- 맥락 기반 게이트(가능하면 연동):
  - 보호 플러그인(예: WorldGuard/GriefPrevention)과 연동해 “보호 구역 내 파괴 시 가중치↑”
  - 좌표를 저장하지 않더라도, “보호 구역 ID/플래그” 정도는 저장 가능(해시/정수 ID)
- 이벤트 기간 게이트:
  - 서버 이벤트/리셋/대형 건축일에는 임계치 조정(운영자가 스케줄로 제어)

## 6) 알림(권장 UX)
- 레벨 1(주의): 스태프 채널에 요약(플레이어, 시간창, 상위 신호 2~3개)
- 레벨 2(경계): `/tp` 추천(“최근 5분 컨테이너 파괴 20, WE replace 3회”)
- 레벨 3(위험): 자동 조치(옵션) — 임시 WE 차단/쿨다운/로그 강화 등 “되돌릴 수 있는” 완화책부터

## 7) 한계와 원칙
- “좌표/블록 원시 로그” 없이도 조기 경보는 가능하지만, **정확한 단정**은 어렵습니다.
- 목표는 “범인 찾기”가 아니라 “빠른 상황 인지 + 피해 최소화”입니다.
- 자동 제재는 반드시 오탐 대응(예외/화이트리스트/재현 로그)과 함께 설계해야 합니다.
